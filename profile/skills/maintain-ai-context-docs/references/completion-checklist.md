# 1. 完成前检查

- 是否说明读取了哪些文档和代码，以及为什么读取
- 是否基于当前代码、测试和 diff，而不是只基于需求设想
- 新增内容是否命中 [writing-ai-retrieval-doc](writing-ai-retrieval-doc.md) 里的写入门槛：能减少后续搜索、定位、判断或排查成本
- 是否优先索引信息（如保留入口、关键跳转点、隐藏规则、兼容边界、验证入口、排查关键词），而非逐步解释源码
- 是否删除、替换或合并了过期、重复、冲突或说明书化内容
- 是否避免罗列完整调用链、普通方法职责、完整测试清单和完整排查手册
- 是否明确兼容性和边界
- 命中写入门槛时，是否维护了需求同级 AI 检索文档；未维护时是否说明跳过依据
- 当同目录存在多个需求文档且容易混读时，是否维护了需求目录入口；未维护时是否说明跳过依据
- 当上层存在或需要顶层入口且能降低加载成本时，是否维护了上层 AI 上下文入口；未维护时是否说明跳过依据
- 是否已在目标目录、入口路由和必要上层目录内识别已有承载文档；不存在时是否避免假设或新建该体系
- 上下文入口是否只在确有前置要求时说明上层承载文档已经承担的读取时机，并避免形成回跳路由或复述其职责、全局读取规则、领域词汇边界、回答要求和治理规则
- 上下文入口是否只保留加载路由、跳过依据、长期文档边界和极少量关键事实
- 是否按 [routing-graph.md](routing-graph.md) 识别项目实际采用的 `startup_carrier`、直接上级、当前节点和直接下级，而非依赖固定文件名
- 每个修改过的非叶子路由节点是否声明命中条件、可定位的下一入口或目标文档，以及停止、跳过或普通源码检索动作
- 需要自动渐进加载的目标检索文档是否能从项目既有 `startup_carrier` 沿有效路由到达；只支持显式访问时是否说明依据
- 文档新增、删除、重命名或移动后，直接上级的路径、标题和触发条件是否同步
- 当前维护范围内是否不存在孤立节点、循环引用和失效目标
- 是否避免创建无助于降低混读或加载成本的中间入口
- 是否避免把 `AGENTS.md`、`domain.md`、`CONTEXT.md`、`CONTEXT-MAP.md` 或其他特定文件体系写成通用依赖
