# 1. 路由图维护契约

本文件只在创建、更新、删除、重命名或移动项目启动路由、AI 上下文入口、AI 检索入口或 AI 检索文档，或检查它们之间的路由连通性时读取。

路由图由三类角色组成，角色由项目实际内容和引用关系决定，不由固定文件名决定：

| role | responsibility |
| --- | --- |
| `startup_carrier` | 项目会按既有 Agent 机制优先读取的规则或索引文档；只声明触发条件、第一跳和未命中时的处理动作 |
| `route_entry` | 按任务目标、能力域或主题声明下一入口、目标 AI 检索文档、补充读取条件和跳过依据 |
| `retrieval_leaf` | 保存长期可检索事实；除必要的事实来源或相关主题引用外，不承担继续展开整棵文档树的职责 |

`AGENTS.md` 可以是 `startup_carrier`，也可以完全不参与 AI 上下文路由。项目也可以使用其他规则文件、索引文件或入口文档。不要把 `AGENTS.md`、`domain.md`、`CONTEXT.md`、`CONTEXT-MAP.md` 或任何三方 Skill 约定的文件写成通用依赖。

# 2. 识别实际路由

只在目标目录、目标文档的真实引用范围和必要上层目录内识别路由：

1. 根据用户指定范围、项目规则和文件内容确认目标节点角色
2. 查找直接引用目标节点的上级文档；只读取能确认命中条件、下一跳和写入范围的相关段落
3. 如果目标节点继续路由，读取其直接下级的路径、标题和必要路由段落，不批量读取下级全文
4. 根据项目既有 Agent 机制确认 `startup_carrier`；无法确认时触发 🔴 CHECKPOINT，不根据常见文件名静默选择
5. 记录从 `startup_carrier` 到目标节点的实际路径；路径不存在时判断应同步直接上级、补充中间入口，还是保持当前文档为显式调用材料

只有项目已有约定、真实引用或用户明确结论才能证明某个文件承担路由角色。目录层级、文件名相似或文件位于项目根目录不构成充分证据。

# 3. 连通性要求

| invariant | requirement | repair |
| --- | --- | --- |
| `next_hop` | 每个非叶子路由节点按任务条件声明一个可定位的下一入口、目标文档或目标章节 | 补充最小路由；无法唯一定位时触发 🔴 CHECKPOINT |
| `stop_action` | 每条路由说明未命中、已足够回答或下级不存在时的停止、跳过或普通源码检索动作 | 补充与当前层职责一致的处理动作，不用全量扫描兜底 |
| `parent_sync` | 新增、删除、重命名或移动节点后，直接上级的路径、标题和触发条件保持有效 | 只同步直接上级；更上层仍能到达时不逐层改写 |
| `startup_reachable` | 需要自动渐进加载的目标节点能从项目既有 `startup_carrier` 沿路由到达 | 在确认的写入范围内补齐最短路径；超出范围时触发 🔴 CHECKPOINT |
| `no_orphan` | 除 `startup_carrier` 和用户明确保留的显式调用材料外，每个路由节点至少有一个有效直接上级 | 补充直接上级引用，或说明为何只支持显式访问 |
| `acyclic` | 当前维护范围内不存在入口互相回指形成的循环 | 删除或改写造成回环的边，保留单向渐进展开 |
| `minimal_depth` | 只有新增一层能降低混读、重复加载或维护成本时才创建入口 | 简单目录由上层直接路由到 AI 检索文档，不为每层目录创建文件 |

# 4. 启动承载文档写入边界

维护 `startup_carrier` 时，只修改其中专门负责 AI 上下文加载的段落：

- 写明哪些任务信号需要进入项目上下文路由
- 指向项目实际存在的第一跳文件或章节
- 写明路由不适用或目标不存在时继续普通源码、配置或文档分析
- 把能力域细分、叶子文档列表和实现事实留给下级入口或 AI 检索文档

用户只指定下级入口或 AI 检索文档时，不静默修改 `startup_carrier`。需要补齐第一跳才能满足 `startup_reachable` 时，先说明目标文件、修改段落和预计影响，触发 🔴 CHECKPOINT。

项目没有既有 `startup_carrier` 时，不自动创建 `AGENTS.md` 或其他项目规则文件。只有用户明确指定新建目标、作用和写入范围后才创建。

# 5. 完成条件

- 已说明识别出的 `startup_carrier`、直接上级、当前节点和直接下级
- 每个修改过的非叶子节点都包含命中条件、下一跳和停止动作
- 新增、删除、重命名或移动节点后，直接上级引用已经同步
- 目标节点的实际可达路径已经确认，或已说明只支持显式访问及其依据
- 当前维护范围内没有孤立节点、循环引用、失效路径或为补齐层级而新增的无效入口
- 没有把项目未采用的固定文件名或三方 Skill 文档体系写入路由
