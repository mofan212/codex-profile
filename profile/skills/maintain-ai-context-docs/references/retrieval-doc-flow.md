# 1. AI 检索文档驱动流程

当触发时指定了 AI 检索文档，按本文件处理。

# 2. 向上查找路由

读取 [routing-graph.md](routing-graph.md)，以此文档的真实引用和必要上层目录为范围，查找最近的直接上级路由节点：

- 找到直接上级后，读取 [context-entry-flow.md](context-entry-flow.md)，按上下文路由驱动流程处理
- 未找到直接上级时，先识别当前项目和文档树，再触发 🔴 CHECKPOINT：询问用户是否以该 AI 检索文档所在目录为起点创建或维护上层路由入口

继续条件：用户确认上层路由目标路径和写入范围。

🛑 STOP：用户只要求分析当前文档，或未确认上层路由写入范围时，不创建入口。

如果用户只指定当前 AI 检索文档但没有要求扩大范围，不要默认读取入口范围内所有 AI 检索文档。

# 3. 直接更新当前检索文档

如果用户明确要求只更新当前 AI 检索文档，不需要扩大到入口路由范围：

1. 读取当前 AI 检索文档
2. 查找同目录同主题需求文档、设计文档或示例数据
3. 检查当前项目 git 变更和相关检索入口、隐藏规则、兼容边界
4. 读取 [writing-ai-retrieval-doc.md](writing-ai-retrieval-doc.md)，然后更新当前文档

不要把入口范围内所有文档作为默认读取对象。

更新后检查直接上级是否需要补充路由；只有路由缺失，或文件新增、删除、重命名、移动时才同步更新。需要修改项目启动承载文档但用户未纳入写入范围时，触发 🔴 CHECKPOINT。
