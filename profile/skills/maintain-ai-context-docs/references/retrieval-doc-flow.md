# 1. AI 检索文档驱动流程

当触发时指定了 AI 检索文档，按本文件处理。

# 2. 检查或更新当前检索文档

用户明确要求扩大到入口范围检查或维护时，执行下一节；其他情况只处理用户指定的当前文档：

涉及当前文档的路由检查时，先读取 [routing-graph.md](routing-graph.md)，再按以下步骤核对文档和事实。

1. 读取当前 AI 检索文档
2. 查找同目录同主题需求文档、设计文档或示例数据
3. 检查当前项目 git 变更和相关检索入口、隐藏规则、兼容边界
4. `operation_mode=check_only` 时，报告过期点、代码依据、建议更新位置和未验证项后结束，不写文件、不询问写入权限
5. `operation_mode=edit` 时，读取 [writing-ai-retrieval-doc.md](writing-ai-retrieval-doc.md)，在已授权范围内更新当前文档

不要把入口范围内所有文档作为默认读取对象。

编辑后需要判断直接上级是否应同步时，读取 [routing-graph.md](routing-graph.md)。只有路由缺失，或文件新增、删除、重命名、移动才同步更新。需要修改项目启动承载文档但用户未纳入写入范围时，触发 🔴 CHECKPOINT，仅暂停该范围的写入。

# 3. 扩大到入口范围检查或维护

只有用户明确要求按上级入口统一检查或维护时，才读取 [routing-graph.md](routing-graph.md)，向上查找最近的直接上级路由节点：

- 找到直接上级后，读取 [context-entry-flow.md](context-entry-flow.md)，按已确认范围继续处理
- 未找到直接上级时，报告路由缺口；只读检查到此结束，需要创建或维护上层入口时，触发 🔴 CHECKPOINT，确认目标路径和新增写入范围后继续

扩大范围未确认时，不读取入口范围内全部文档，不创建入口，仍可完成当前文档的已授权检查或更新。
