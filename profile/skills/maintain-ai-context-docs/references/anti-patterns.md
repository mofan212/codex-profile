# 反例与处理动作

仅在发现候选冲突、跨项目范围、事实来源不足或路由连通性问题时读取。正常路由按 `SKILL.md` 的输入路由、权限表和通用硬规则执行。

| anti_pattern | risk | required_action |
| --- | --- | --- |
| 把需求设想、临时讨论或推测写成已实现代码事实 | 长期检索文档会误导后续排查和实现判断 | 只写代码、测试、diff、已有文档或用户明确结论能支撑的事实 |
| 绕过入口文档批量读取或重写同目录全部 Markdown | 破坏渐进加载，扩大无关上下文和写入范围 | 先查看目录列表和入口文档，再按入口路由读取必要文档 |
| 在多个强匹配或弱匹配候选中静默选择目标文档 | 可能更新错文档或把相关文档误判为目标文档 | 列出候选、匹配依据和预计写入范围，触发 🔴 CHECKPOINT |
| 未确认 workspace 和写入范围时跨项目修改文档 | 越界修改用户未授权项目或文档树 | 先说明目标、原因和预计范围，获得确认 |
| 把 Markdown 润色、需求设计、实现记录或纯查找任务转成 AI 检索文档维护 | Skill 误触发，生成多余长期文档 | 退出本 Skill，按对应任务处理 |
| 把某套项目或三方 Skill 的文件名写成通用前置条件 | 路由维护与实际项目机制脱节 | 识别项目既有启动承载文档和路由节点，只写真实存在或已确认创建的文件 |
| 新增检索文档或入口后只更新当前文件 | 下级文档无法从启动路由到达，或保留失效、循环引用 | 按 [routing-graph.md](routing-graph.md) 同步直接上级并验证完整路径 |
