# 1. 兜底输入流程

本文件只在无法直接进入需求文档、AI 上下文入口或 AI 检索文档分支时读取。

# 2. 没有指定文档

如果用户没有指定任何文档：

1. 识别当前所在项目
2. 查看项目根、文档根或常见文档目录的文件列表，并根据项目规则、真实引用和文件内容识别既有启动承载文档、上下文入口与 AI 检索文档；常见 AI 文档名只能作为候选，不能替代实际路由证据
3. 沿用用户已明确的检查或维护范围；范围仍不明确时，说明候选目录和预计读取范围，只询问最关键的范围问题
4. `operation_mode=check_only` 时，在明确范围内检查并报告，不询问写入权限；`operation_mode=edit` 时，再按写入权限处理必要的新增或扩大范围确认

不要默认全量扫描和重写。

如果当前项目没有明显文档目录，先根据 `git status`、构建文件和目录名判断候选范围；仍无法判断时询问用户提供文档根目录。

# 3. 其他文档或错误触发

当用户指定了文档，但诉求明确是普通 Markdown 润色、表格排版、格式化或错别字修正时：

1. 说明该请求不属于 AI 检索文档维护
2. 不读取 AI 检索 reference，不生成 AI 检索说明
3. 退出本 Skill，按普通 Markdown 文档任务继续处理
4. 只有用户要求转为 AI 检索文档维护时，才重新进入本 Skill

当用户指定了文档，但它不是需求文档、AI 上下文入口或 AI 检索文档时，先询问用户，不要直接生成文档。

说明正确触发方式：

| input | next_action |
| --- | --- |
| 指定一个需求文档 | 结合代码变更生成或更新同目录 AI 检索说明 |
| 指定项目既有启动承载文档中的 AI 上下文路由段落 | 维护第一跳、直接下级和路由连通性，不默认读取全部 AI 检索文档 |
| 指定一个 AI 上下文入口 | 根据变更需求文档、路由连通性或用户确认的范围维护 |
| 指定一个 AI 检索文档 | 默认检查或更新当前文档，只有明确要求扩大范围时才按上级入口维护 |
| 不指定文档但指定模块、功能、能力域、接口、类名、包名或业务流程，并要求维护 AI 检索类文档 | 先定位候选 AI 检索文档和建议路径 |
| 不指定文档 | 先定位候选文档，范围不明确时再确认检查或维护范围 |
