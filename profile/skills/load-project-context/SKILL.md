# 1. 激活确认与加载目标

本 Skill 只消费项目已有的 AI 上下文入口、AI 检索入口和 AI 检索说明，不替代项目规则读取、普通 Markdown 阅读或常规源码分析。触发后先确认加载模式，再决定是否继续读取：

| mode | condition | action | stop_when |
| --- | --- | --- | --- |
| `routed_context` | 任务直接指向 AI 上下文/检索入口或检索说明；或代码解释、设计与修改依赖项目领域语义，且已确认存在相关路由 | 按第 2 节定位入口并渐进加载 | 路由与当前任务无关 |
| `explicit_load` | 用户明确要求加载项目上下文，但没有给出入口 | 只查看候选文档目录的文件列表，识别第 2 节入口或明确命名的 AI 检索文档 | 🛑 STOP：不存在相关入口或检索文档时，结束本 Skill 的加载流程并继续原任务 |
| `not_applicable` | 普通代码解释、源码搜索、局部修改、测试或项目启动；项目只有 `README.md`、`AGENTS.md`、`index.md` 等常规文件 | 🛑 STOP：不读取本 Skill 正文之外的项目上下文，按普通任务处理 | 不把常规文件改判为 AI 上下文体系 |

领域语义包括业务状态、能力域、产品/渠道/流程名、需求专有名词和跨项目模块概念。类名、包名、后缀或实现复用关系只能作为检索线索，不能单独证明存在领域语义或触发本 Skill。

`AGENTS.md` 是项目行为约束，不是本 Skill 的知识上下文入口；运行环境或普通任务可以按既有机制读取它，但不得据此激活或扩大本 Skill 的加载范围。

# 2. 目录入口优先级

当任务需要加载文档目录时，必须先查看该目录下的文件列表和文件名，不要直接批量读取全部文档内容。

候选范围按以下顺序确定：

1. 用户明确指定的文件、目录或文档标题
2. 当前项目边界内通过文件名搜索命中的 `00-AI上下文入口.md`、`AI上下文入口.md`、`AI检索入口.md`
3. 当前项目边界内文件名包含 `AI检索说明`、`AI检索文档`、`AI排查文档` 的文件

第 2、3 步只查看路径和文件名，不预读内容。当前项目内没有命中时，按第 4 节停止加载；除非入口、构建配置或用户请求明确涉及跨项目事实，否则不得搜索父目录或兄弟项目。

按以下顺序查找入口，优先读取第一个覆盖当前任务的入口：

1. `00-AI上下文入口.md` — 读取该入口，根据其中的加载路由、文档定位、适用场景或引用说明继续读取
2. `AI上下文入口.md` — 同上
3. `AI检索入口.md` — 同上
4. 用户明确指定或任务能唯一定位的 AI 检索说明、AI 检索文档或 AI 排查文档

`README.md`、`AGENTS.md` 和普通 `index.md` 不是降级入口。只有已命中的 AI 入口明确路由到这些文件，或用户直接要求读取对应文件时，才按普通文档读取；不得因为 AI 入口缺失而用它们延长本 Skill 的加载流程。

加载入口后，先按入口指向的相关文档继续。当前入口不能覆盖任务时，再尝试下一优先级 AI 入口；所有入口均不能覆盖时，说明上下文缺口并回到普通源码或文档处理，不扫描同目录其他 Markdown。

# 3. 按需加载规则

用户明确要求全量审查、汇总、迁移或上下文重建时，可读取同目录下全部相关 Markdown，跳过文件名或入口说明表明与任务无关的文档，不再逐条判断下表场景。

其余情况按下表场景叠加执行：

| scenario | action | skip_when |
| --- | --- | --- |
| 目录下不存在相关 AI 入口或检索文档 | 结束本 Skill 的加载流程，继续普通源码或文档任务 | 不以 `README.md`、`AGENTS.md`、`index.md` 兜底 |
| 需求文档、AI 检索说明、设计文档、实现记录同时存在 | 优先读取 AI 检索说明或上下文入口，按需补充原始需求或详细设计 | AI 检索说明已足以回答当前问题 |
| 入口路由、文件名日期/版本、文档标题或正文弃用声明能证明新旧关系 | 优先读取明确标记为当前版本的集成说明、AI 检索说明或上下文入口 | 只有目录顺序、文件时间或内容相似，无法证明新旧关系 |
| 读取过程中发现引用了更合适的上下文文档 | 按引用继续读取被指向文档 | 引用文档只解释历史背景且当前任务不需要 |
| 代码问题依赖项目领域语义且存在相关路由 | 先读取 AI 上下文/检索入口和路由指向的术语或检索文档，再读取源码本体和必要调用链 | 代码本身足以回答，或不存在相关路由 |
| AI 入口路由到 `README.md` 或 `index.md` | 只读取入口明确指向的章节或文件 | 文件未被入口引用且用户未直接指定 |

# 4. 异常与失败模式

| failure | action | fallback |
| --- | --- | --- |
| 相关入口或检索文档不存在 | 结束本 Skill 的加载流程，说明未发现结构化上下文 | 继续普通源码或文档任务；用户已明确指定普通文档时直接处理该文档 |
| 入口文档不可读或内容为空 | 记录不可读路径，继续尝试下一优先级 AI 入口 | 所有入口均不可读时停止加载，不基于文件名编造文档事实 |
| 多个入口同时命中 | 按第 2 节入口优先级读取第一个命中的入口 | 第一个入口不能覆盖当前任务时，再读取下一优先级入口 |
| 入口路由不能覆盖当前任务 | 读取下一优先级 AI 入口 | 仍不能覆盖时说明上下文缺口，回到普通源码或文档处理 |
| 入口或文档之间事实冲突 | 优先采用最新 AI 上下文入口、AI 检索说明或集成说明 | 冲突影响结论时，不直接下结论，列出冲突点 |
| Workspace 候选项目超过一个 | 根据模块名、包名、文档路径或构建配置筛选强相关项目 | 仍有多个强候选时触发 CHECKPOINT |

# 5. Workspace 文档边界

当文档任务涉及当前项目外的模块、仓库或子项目时，按下表确认 Workspace 文档边界；本节只约束文档读取，不替代源码调研、调用链确认或跨项目写入确认规则。

兄弟项目只有满足以下至少一项可验证信号时，才算强相关候选：AI 入口明确指向其路径；构建配置声明对应模块或依赖；用户点名的模块、包名或仓库名与候选项目完全匹配。仅目录相邻、名称相似、类名相同或存在实现复用，不构成强相关证据。

| trigger | action | forbidden |
| --- | --- | --- |
| 文档引用当前项目外的模块、仓库或子项目 | 先识别当前项目的上级 Workspace，并按需查看同一 Workspace 下兄弟项目或聚合仓库中的相关文档 | 只在当前项目根目录内检索后断言其不存在 |
| 无法判断 Workspace 边界 | 先查看当前项目父目录下的项目列表，再根据模块名、包名、文档路径或构建配置判断相关项目 | 在未确认边界时直接下结论 |
| 需要跨项目读取文档事实 | 可以直接读取相关兄弟项目或聚合仓库中的文档 | 把未读取的跨项目文档事实当作不存在 |

# 6. CHECKPOINT 与停止条件

| trigger | checkpoint | action |
| --- | --- | --- |
| 需要从当前项目扩展到多个兄弟项目、聚合仓库或上级 Workspace | 🔴 CHECKPOINT：读取范围扩大 | 先说明候选项目、读取理由和预计读取入口；范围不明确时询问用户 |
| 用户要求全量审查、迁移、汇总或上下文重建，且范围跨出当前目录或当前项目 | 🔴 CHECKPOINT：全量读取 | 先列出拟读取目录和跳过规则，再继续 |
| 用户要求生成、更新、补充、重写、检查是否过期或归档 AI 检索文档、AI 排查文档、AI 上下文入口或 AI 检索入口 | 🛑 STOP：任务转为维护文档 | 停止按本 Skill 扩大读取范围，交接 `$ai-retrieval-docs` |

# 7. Skill 切换交接

| condition | target_skill | carry_context | stop_rule |
| --- | --- | --- | --- |
| 任务从读取文档转为维护 AI 检索文档、AI 排查文档、AI 上下文入口或 AI 检索入口 | `$ai-retrieval-docs` | 已读取的入口文档、路由依据、相关文档路径、跳过依据、仍需确认的问题 | 停止按本 Skill 扩大读取范围，由 `$ai-retrieval-docs` 判断写入边界、事实依据和是否需要询问用户 |
| 用户只要求理解、定位、汇总或基于文档回答问题，没有要求维护 AI 检索或入口文档 | 保持本 Skill | 已读取文档、读取理由、可选的下一步上下文 | 不写入 AI 检索文档或入口文档 |
| 没有相关 AI 入口或检索文档，或现有路由不能覆盖任务 | 退出本 Skill | 已检查的候选目录、未命中的入口名称、上下文缺口 | 按普通源码或文档任务继续，不要求用户为非阻塞缺口确认 |

# 8. 反例与黑名单

| forbidden | reason |
| --- | --- |
| 不要因为项目只有或常规读取 `README.md`、`AGENTS.md`、`index.md` 就触发本 Skill | 这些文件由普通项目流程处理，不构成结构化 AI 上下文体系 |
| 不要在 AI 入口缺失时扫描任意项目文档寻找替代入口 | Skill 已经失去渐进加载路由，继续扫描只会扩大上下文 |
| 不要因为文档在同一目录就批量读取全部 Markdown | 会破坏渐进加载，增加无关上下文 |
| 不要跳过 AI 上下文入口或 AI 检索入口直接读 README | 入口文档是上下文路由的优先事实来源 |
| 不要把类名、包名、后缀或实现复用关系直接解释成领域概念 | 领域含义必须由术语表、需求、设计或检索文档支撑 |
| 不要只在当前项目内搜索后断言兄弟项目文档不存在 | 涉及跨项目事实时必须确认 Workspace 边界 |
| 不要用本 Skill 生成或更新 AI 检索文档、AI 排查文档或上下文入口 | 写入类任务应交接 `$ai-retrieval-docs` |

# 9. 输出要求

| field | requirement |
| --- | --- |
| `activation_result` | 说明本 Skill 是否继续加载；如果退出，只需说明未命中结构化入口或任务不依赖路由，不强制输出其余字段 |
| `loaded_context` | 在回答、设计方案或修改代码前，说明当前加载了哪些文档、入口或领域上下文 |
| `load_reason` | 说明为什么加载这些上下文 |
| `skipped_context` | 如果跳过同目录下其他文档或入口，基于入口文档、文件名、标题或任务目标说明其暂时无关 |
| `next_context` | 如果仍需补充上下文，说明下一步应该读取什么以及触发条件 |
