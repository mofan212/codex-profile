# 1. 建档协议

通过 `$feat` 手动调用进入 `draft_requirement` 时，按以下步骤执行：

1. 定位需求文档集合目录
2. 判断需求文档集合采用能力域目录还是独立需求目录
3. 用最多 15 个字概括用户描述，作为需求简述
4. 确定目标目录
5. 计算目标目录内的需求序号
6. 在目标目录下创建 `<需求序号>-<需求简述>-需求文档.md`
7. 读取 [requirement-template.md](requirement-template.md)，根据用户已提供信息填入草稿
8. 不臆造业务规则、验收标准、实现方案或代码事实；未知内容保留为空或写成待完善项

需求文档集合按能力域组织时，目标目录使用项目约定的能力域名称；按独立需求组织时，目标目录使用需求简述。

# 2. 文档目录定位

按下表从上到下判断：

| priority | condition | action |
| --- | --- | --- |
| 1 | 用户明确指定目标目录 | 使用用户指定的目标目录 |
| 2 | 用户只指定需求文档集合目录 | 以该目录为范围，继续按后续规则判断组织方式和目标目录 |
| 3 | 项目约定、领域文档或需求文档集合的现有结构明确按能力域组织，且能唯一确定本需求所属的能力域 | 使用项目约定的能力域名称，已有目录时直接复用，不存在时按该名称创建 |
| 4 | 需求文档集合明确按一个需求一个目录组织 | 用需求简述创建独立需求目录 |
| 5 | 集合目录整体组织方式不明确，但能根据已有同类需求文档唯一确定组织方式和目标目录 | 沿用同类需求的组织方式，使用已确定的目标目录 |
| 6 | 无法唯一确定目标目录，包括组织方式不明、能力域名称不明或存在多个候选目录 | 🔴 CHECKPOINT：列出已识别的候选（如有），请用户确认目标目录；需要新建时，同时确认采用能力域名称还是需求简述，采用能力域名称时确认具体名称 |

目标目录（包含所在集合目录和目录名）已唯一确定后继续。能力域模式下，组织方式已明确但具体能力域名称未知时，仍执行上述 CHECKPOINT；不要默认新建需求同名目录。

# 3. 目录与需求命名规则

| 规则 | 要求 |
| --- | --- |
| 能力域模式 | 使用项目约定的能力域名称，例如 `数据转换节点`，已有目录时直接复用，不存在时按该名称创建 |
| 独立需求模式 | 使用需求简述作为目录名，例如 `订单超时关闭` |
| 需求简述 | 基于用户原始描述概括本次变化，不引入用户未提到的业务对象 |
| 长度 | 需求简述最多 15 个汉字，英文、数字和符号按实际字符计入 |
| 风格 | 使用简短名词短语，例如 `对象转换为Map`、`订单超时关闭` |
| 禁止 | 不使用个人姓名、账号、机器路径、日期时间、阶段词或泛称，例如 `新需求`、`需求文档`、`功能开发` |
| 文件名 | 需求文档名必须是 `<需求序号>-<需求简述>-需求文档.md` |

# 4. 需求序号规则

编号文件指目标目录内的 `<编号>-*-需求文档.md` 和 `<编号>-*-AI检索说明.md`。按下表从上到下匹配，命中一行后停止：

| condition | action |
| --- | --- |
| 目标目录已有编号文件，但存在多种编号格式或无法可靠判断格式 | 🔴 CHECKPOINT：列出候选格式并请用户确认；确认后继续 |
| 目标目录已有编号文件，且编号格式一致 | 两类文件共享编号序列；取最大编号加 `1`，保持编号位数和前导零，不扫描其他目录 |
| 目标目录没有编号文件，其他同级目标目录采用相同组织方式，且编号格式一致 | 只沿用编号位数和前导零格式，从 `1` 开始，不继承其他目录的最大编号 |
| 目标目录没有编号文件，其他同级目标目录采用相同组织方式，但存在多种编号格式或无法可靠判断格式 | 🔴 CHECKPOINT：列出候选格式并请用户确认；确认后继续 |
| 目标目录没有编号文件，且没有可参考的同级目标目录 | 从 `01` 开始 |
